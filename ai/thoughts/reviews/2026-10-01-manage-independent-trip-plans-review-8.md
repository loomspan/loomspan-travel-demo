## Findings

### [P2] Restore the booking-review return destination with history

- Location: `frontend/src/components/IndependentPlansWorkspace.tsx:133`.
- Scenario: Open comparison, enter a plan's booking review, return to workspace and enter workspace booking review; then use browser history to revisit the earlier comparison review. The popstate handler restored the plan, compared IDs and review view but retained the most recent `reviewReturn` value.
- Impact: The displayed review's Back action returned to workspace instead of its originating comparison, breaking the preserved comparison/review navigation requirement (AC14).
- Evidence: A focused pre-fix DOM regression restored valid comparison-review history and failed to find `Comparing 2 plans` after Back; workspace rendered instead. The final regression captures the history actually generated by comparison→review, then revisits it after workspace review.
- Fix: Restore `reviewReturnView` alongside the other history fields, using the existing workspace default for older entries.

### [P2] Preserve explicitly unknown purchased traveler ages

- Location: `frontend/src/components/BookingConfirmationView.tsx:20`.
- Scenario: V21 preserves a legacy purchase with unknown ages as `purchasedTravelerAges: null`; independent planning later supplies new ages. Confirmation used nullish coalescing to fall back to current planning ages.
- Impact: Booking details claimed the edited planning ages were purchased facts, contrary to frozen and faithfully displayed historical context (AC8). The migration intentionally preserves unknown ages; there is no source basis for replacing them with later inputs.
- Evidence: The pre-fix focused regression rendered an explicit null purchased age list alongside planning `[30, 28]`, and failed because confirmation displayed `(ages: 30, 28)`.
- Fix: Preserve explicit null. Retain the compatibility fallback only when the purchased field is absent (`undefined`).
